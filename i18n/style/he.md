- Commands, buttons, and action menu items use a concise masculine singular imperative. Use the same verb for the same action throughout the app. (Download — הורד; Pause — השהה)
- Checkbox labels describe a setting or outcome; do not phrase them as commands. Use a short noun phrase. (Start downloads automatically — הפעלה אוטומטית של הורדות; Show notifications — הצגת הודעות)
- Address the user directly only when needed. Hebrew has no formal second-person distinction; use masculine singular imperative as the conventional UI form, or an infinitive/noun phrase to avoid addressing the user. (Enter a URL — הזן כתובת URL; To continue — להמשך)
- Keep the register clear, neutral, and helpful. Avoid slang, overly formal wording, and unnecessary personal pronouns. (The download is complete — ההורדה הושלמה; Not: ההורדה שלך הושלמה)
- Phrase confirmation prompts as concise questions that state the action and object. Avoid a bare yes/no question when the consequence could be unclear. (Delete this download? — למחוק את ההורדה הזו?; Buttons: מחק / ביטול)
- Use compact noun phrases for labels and column titles. Include the definite article or a preposition when Hebrew grammar requires it; do not add them mechanically. (File name — שם הקובץ; Download speed — מהירות הורדה)
- Prefer natural Hebrew word order: put adjectives after nouns and place את before a definite direct object. Reorder placeholders when needed for fluent Hebrew. (Completed downloads — הורדות שהושלמו; Open the file — פתח את הקובץ)
- Use concise status wording. For ongoing actions, choose a natural Hebrew construction rather than copying an English participle or ellipsis mechanically. (Checking... — מתבצעת בדיקה…; {n} downloading — הורדות פעילות: {n})
- Make agreement follow the expressed Hebrew noun, even when English leaves the subject implicit. Prefer noun-based status text if the implied subject is unclear. (The download is complete — ההורדה הושלמה (feminine); The file is ready — הקובץ מוכן (masculine))
- Localize error fragments as complete, idiomatic Hebrew messages where possible; retain a colon before a supplied error detail. (Could not be opened: {error} — לא ניתן לפתוח: {error}; Could not open the file: {error} — לא ניתן לפתוח את הקובץ: {error})
- Write event-log entries as brief, factual statements, usually in the past tense or as a noun phrase. Do not address the user. (Download started — ההורדה התחילה; Connection lost — החיבור נותק)
- Hebrew has no uppercase and lowercase distinction. Do not capitalize words for emphasis or use English-style title case; preserve the official spelling of product and file-format names. (Download settings — הגדרות הורדה; ZIP file — קובץ ZIP)
- Write month and weekday names in lowercase in running text. Use the standard Hebrew names. (Sunday, June 2 — יום ראשון, 2 ביוני; Monday — יום שני)
- Use Hebrew punctuation and spacing: no space before a comma, period, colon, or question mark; use one space after punctuation where the sentence continues. Prefer the ellipsis character … for an unfinished status. (Error: {error} — שגיאה: {error}; Checking… — מתבצעת בדיקה…)
- Use quotation marks only when they clarify a literal value, file name, or quoted text. Keep quotation marks paired and do not add them around ordinary UI labels. (File ״report.zip״ was added — הקובץ ״report.zip״ נוסף; Open Settings — פתח את ההגדרות)
- Use Hebrew forms for established technical concepts rather than phonetic English borrowings. Retain Latin text for URLs, extensions, and official names. (Download — הורדה; URL — כתובת URL)
- Preserve placeholders exactly and place them where they read naturally in Hebrew. Ensure the surrounding noun agrees with the displayed number and use the product's plural rules. ({n} files — {n} קבצים; {n} active downloads — {n} הורדות פעילות)
- Use the same Hebrew term for the same concept in buttons, menus, statuses, and help text. Distinguish an action from its noun form where Hebrew requires it. (Pause — השהה; pause (noun) — השהיה; Upload — העלה; upload (noun) — העלאה)
- Avoid unnecessary abbreviations and literal English syntax. If a short label would be ambiguous, use a slightly fuller Hebrew phrase. (Check for updates — בדוק אם קיימים עדכונים; Not a literal fragment: בדוק עדכונים)
