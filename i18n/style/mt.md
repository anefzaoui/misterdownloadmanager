- Use the direct, concise style of Windows interface text. Address the user as singular ‘you’; normally omit the pronoun and use a direct imperative for an action. (Agħżel folder.; Daħħal l-indirizz.)
- Phrase action commands as imperatives. Keep the verb first where natural; use the same wording for the same action throughout the app. (Ibda t-tniżżil.; Iftaħ il-ħolqa.)
- Use concise imperatives for buttons. Use a noun only when it names a destination or a setting rather than an action. (Issospendi; Settings)
- Phrase menu actions as imperatives; phrase menu headings as short nouns. (Żid tniżżil; Fajl)
- Make check box text a short statement describing the option’s effect, not a command to the user. (Uri t-tniżżil komplut)
- Use direct confirmation questions with a question mark. Do not add a separate ‘Are you sure?’ when the action can be named clearly. (Trid tħassar dan it-tniżżil?)
- Keep labels and column headings short, usually as noun phrases without an article. Use prepositions when they clarify the relationship. (Isem; Daqs)
- Use concise status wording. For an ongoing action, use ‘qed’ with the verb; use a noun phrase when it reads more naturally. (Qed jiċċekkja…; Tniżżil għaddej)
- Make number agreement clear in progress and status text. Prefer naming the counted items instead of leaving a number next to a verb whose agreement is unclear. (Qed jitniżżlu {n} fajls)
- In fragments with an implied subject, make the verb agree with the understood noun. If the subject is unclear, recast the text as a noun phrase. (Qed jitniżżel il-fajl.; Qed issir verifika.)
- Keep error messages brief and specific. Use a colon before a supplied error detail; make the verb agree with the item named or implied. (Ma setax jinfetaħ: {error})
- Write event log entries as concise, complete statements, normally in the past tense. Include a full stop for a sentence. (It-tniżżil beda.)
- Use sentence case, not English-style title case. Capitalize the first word and proper names; keep month and weekday names lowercase in running text. (Settings tat-tniżżil; it-Tnejn, 12 ta’ jannar)
- Use Maltese spelling and diacritics, including ċ, ġ, ħ, ż, and the Maltese apostrophe where required. Preserve the spelling of filenames, URLs, and product names. (Iċċekkja għal aġġornamenti; Fajl ‘setup.exe’)
- Use one space between words and after punctuation, never before commas, full stops, colons, or question marks. Do not put a space before an ellipsis. (Żball: il-fajl ma nfetaħx.; Qed jiċċekkja…)
- Use typographic double quotation marks for quoted interface text where supported. Do not use quotation marks around ordinary labels or button names. (Il-messaġġ “Tniżżil lest” intwera.)
- Use the apostrophe consistently in Maltese contractions and elisions; do not add spaces around it. (ta’ dan il-fajl; l-indirizz)
- Prefer natural Maltese word order, putting the action or key information early. Avoid copying English word order if it sounds unnatural. (Agħżel il-folder fejn trid issalva l-fajl.)
- Prefer established Maltese technical terms. Use a familiar loanword when it is established in computing; avoid inserting English just because it is shorter. Keep product names and technical identifiers unchanged. (aġġornament; folder)
- Keep placeholders unchanged and place them where Maltese grammar requires. Avoid making a placeholder carry an ending or a gender that cannot be guaranteed. (Qed jitniżżlu {n} fajls.; Żball: {error})
